# InferHub Desktop 0.4.0

Will it fit? (node phase 118). It needs a node at **3.79 or later**. The node in every package is 3.79.0.

## What is new

- **Check fit…** beside Pull on the Models tab. Paste a Hugging Face link, `owner/repo`, or an Ollama name like
  `qwen2.5:7b`, then say how much context you need. Type it (`32k`, `128K`, `40960`) or pick one of the quick
  buttons, which go up to the model's own trained context. There is no minimum.
- The dialog shows the node's answer:
  - one line for the model (size, experts, trained context) and one for this machine (the card, the RAM);
  - one row per engine that can run the model. Each row has its best size, where the model would sit (all on the
    card, experts in RAM, split, CPU, from disk), how fast that is likely to be, and the node's reasons with the
    numbers. Strata's and colibri's rows come from their own planners.
- Pick another size from the row's box, and press **Install**. The node downloads the model for that engine with
  the context you chose. The progress shows on the Models tab, as for a pull. An option the node says does not
  fit asks before **Install anyway**.
- **Settings → Engines** has `Colibri:Serve:Vulkan`, which runs colibri on the graphics card.

## Not signed

Still unsigned. **Windows** SmartScreen: *More info → Run anyway*. **macOS**: right-click `InferHub.app` → *Open* →
*Open*, or `xattr -dr com.apple.quarantine InferHub.app`.

## Not established

On Windows the app, built from source, was attached to a 3.79 node running Ollama, a Vulkan llama.cpp, colibri
and Strata. The dialog was rendered from that node's live answers. **Install was not clicked in the window.** The
same request was sent to the node with `curl` and ran. The Linux and macOS packages are still built by CI only.
